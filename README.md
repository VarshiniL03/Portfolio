# Personal Portfolio Platform

A full-stack portfolio site with an admin-editable content system and a retrieval-augmented AI chatbot.

- **Frontend:** React + Vite + Tailwind CSS
- **Backend:** FastAPI (Python)
- **Database:** PostgreSQL + pgvector
- **Chatbot:** RAG pipeline — Cohere (embeddings) + Groq (LLM) via LangChain/LangGraph
- **Deployment:** Vercel (frontend) · Render (backend) · Neon (database)
- **CI/CD:** GitHub Actions → auto-deploy on every push to `main`

---

## 1. Features

- Fully responsive, dark-themed homepage: Hero, About, Experience, Projects, Education, Achievements, Resume download, Contact
- Secure admin dashboard (JWT auth, role-based access) to manage all content without touching code
- AI chatbot grounded in real portfolio data via **RAG**:
  - Visitor questions are embedded (Cohere) and matched against a `pgvector` index of the portfolio's actual content
  - Answers are generated by an LLM (Groq) using only retrieved context — strict guardrails prevent hallucination and off-topic answers
  - Structured "actions" (resume download button, email compose link, LinkedIn icon) are detected server-side and rendered as real UI elements, not plain text links
  - Conversation memory and automatic query reformulation via LangGraph
- Resume upload/download, admin-manageable FAQ knowledge base
- Rate-limited auth and chatbot endpoints, bcrypt password hashing, CORS lockdown

## 3. Local setup

### Prerequisites
- Node.js 20+, Python 3.11+, Docker

### Steps
```bash
# 1. Environment
cp backend/.env.example backend/.env      # fill in SECRET_KEY, DATABASE_URL, GROQ_API_KEY,
                                            # COHERE_API_KEY, FIRST_ADMIN_EMAIL/PASSWORD
cp frontend/.env.example frontend/.env    # leave VITE_API_BASE_URL blank for local dev

# 2. Database (pgvector-enabled Postgres image)
docker compose up -d db

# 3. Backend
cd backend
pip install -r requirements.txt
alembic upgrade head
python -m scripts.create_admin
python -m uvicorn app.main:app --reload

# 4. Frontend (new terminal)
cd frontend
npm install
npm run dev
```

Visit `http://localhost:5173`. Admin panel: `http://localhost:5173/admin/login`.

**After adding/editing content**, go to Admin → Dashboard → **"Reindex Knowledge Base"** so the chatbot can retrieve it.

## 4. Environment variables

### Backend (`backend/.env`)
| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Signs JWTs — generate with `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `DATABASE_URL` | Postgres connection string |
| `ALLOWED_ORIGINS` | JSON array of allowed frontend origins (CORS) |
| `GROQ_API_KEY` / `GROQ_MODEL` | Chatbot LLM |
| `COHERE_API_KEY` | Chatbot embeddings |
| `STORAGE_BACKEND` | `local` or `s3` (resume uploads) |
| `FIRST_ADMIN_EMAIL` / `FIRST_ADMIN_PASSWORD` | Used once by `create_admin.py` |

### Frontend (`frontend/.env`)
| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Blank for local dev (Vite proxies to `localhost:8000`); full backend URL + `/api/v1` in production |

**Never commit `.env` files** — they're gitignored. Only `.env.example` (with placeholder values) should be tracked.

## 5. How the chatbot works

1. On save/edit, admin clicks **"Reindex Knowledge Base"** → `services/indexer.py` turns experience, projects, education, achievements, FAQs, and site content into text chunks, embeds each via Cohere, and stores them in `knowledge_chunks` (with a `pgvector` column).
2. A visitor's question is embedded the same way, and `pgvector`'s cosine distance operator finds the most relevant chunks directly in SQL.
3. Certain high-value fields (name, about, resume link, contact, education, experience, achievements, tech stack) are **always** included in the prompt regardless of retrieval match — this guarantees reliable answers to common questions instead of depending purely on similarity search.
4. A strict, few-shot-prompted system prompt instructs the LLM to answer only from provided context, refuse off-topic questions with a fixed message, and never fabricate specifics.
5. Server-side keyword detection (not the LLM) decides when to attach structured "actions" — e.g. asking about a resume attaches a real download button; asking about contact attaches an email/LinkedIn button.
6. The LangGraph version (`chat_graph.py`) adds short-term conversation memory and one automatic query-reformulation retry if the first retrieval attempt finds nothing relevant.

## 6. Deployment

| Layer | Platform | Notes |
|---|---|---|
| Frontend | **Vercel** | Auto-deploys on push to `main`. Set `VITE_API_BASE_URL` in Vercel env vars. |
| Backend | **Render** | Free tier spins down after 15 min idle (~30-60s cold start on next request). Deploys via the included `Dockerfile`. |
| Database | **Neon** | Free tier auto-suspends compute after inactivity, auto-wakes on next query. pgvector enabled via `CREATE EXTENSION IF NOT EXISTS vector;` in Neon's SQL Editor. |

**Every `git push` to `main` auto-redeploys both frontend and backend** — no manual redeploy needed for code changes. New database migrations still need to be applied manually (the Dockerfile's `CMD` runs `alembic upgrade head` automatically on every container start, so this is largely automatic too).

**Local and production are separate databases** — content added via `localhost:5173/admin` does not appear on the live site, and vice versa. Enter real content directly through the live admin panel.

### One-time production setup
1. Create a Neon project, enable pgvector, copy the connection string
2. Deploy backend to Render (Root Directory: `backend`), add all env vars from the table above
3. Deploy frontend to Vercel (Root Directory: `frontend`), set `VITE_API_BASE_URL`
4. Update Render's `ALLOWED_ORIGINS` to the live Vercel URL
5. Log into the live admin panel, add real content, click Reindex Knowledge Base

## 7. Security notes

- Passwords hashed with bcrypt; JWTs signed with `SECRET_KEY` (use a different value in local vs. production)
- `/auth/login` and `/chatbot/message` are rate-limited per IP
- Two roles: `admin` (can manage users) and `editor` (can manage content only)
- Resume uploads restricted to PDF, 5MB max, randomized filenames
- Vercel's Deployment Protection should be **disabled** for the production deployment, or visitors will be prompted to sign into Vercel before seeing the site

## 8. Troubleshooting

- **Chatbot gives generic/wrong answers** → check `MAX_DISTANCE` and few-shot examples in `chatbot.py`/`chat_graph.py`; make sure content is filled in and reindexed
- **`groq.APIConnectionError` / `Illegal header value`** → check `GROQ_API_KEY` for a trailing newline or whitespace — a very easy copy-paste mistake
- **Admin login "incorrect password" on a live deploy after changing `FIRST_ADMIN_PASSWORD`** → changing this env var does NOT update an existing account; delete the user row via Neon's SQL Editor and let it recreate on next deploy
- **Render deploy times out** → avoid running `create_admin.py` on every startup once the account already exists; keep the Dockerfile's `CMD` to just `alembic upgrade head && uvicorn ...`
- **CORS errors in production** → confirm Render's `ALLOWED_ORIGINS` exactly matches the live Vercel URL
- **Vercel site asks visitors to sign in** → disable Deployment Protection in Vercel project settings
